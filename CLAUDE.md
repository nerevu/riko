# riko

Python stream processing engine modeled after Yahoo! Pipes.

This file holds the index plus the correctness invariants. Long-form detail lives in `_docs/`:

- `_docs/INTERNALS.md` — codegen rules, discovery/export surfaces, tooling gotchas
- `_docs/DOCUMENTATION_STANDARD.md` — **read before writing docstrings/doctests**
- `_docs/PHASE_CHECKLISTS.md` — live status (start here); `_docs/ROADMAP.md` — gameplan index

## Async Backend

Backend is `anyio` when the `async` extra (`anyio` + `httpx`) is installed, else `empty` (sync-only).
There is **no Twisted** and **no `RIKO_ASYNC_BACKEND` env var** — selection is purely "does `anyio`
import?" in `bado/__init__.py` (`backend = "empty" if run is None else "anyio"`).

## Correctness invariants (audit remediation)

Non-obvious decisions from an audit + source review — don't silently revert them. General rule:
**prefer `is None`/`is not None` over truthiness** wherever `0`/`False`/`""` are valid values.
`coroutine` marks pub/sub generator pipelines (`send`/`receive`), **not** async; `return_value` is removed.

- **Immutable modules** — `Module.prepare()` returns a frozen `PreparedModule`; there is no prepare cache, so call-site options never leak across items or concurrent invocations. (The earlier `_prepare_key` cache was removed: it dropped call-site options and was unsafe under concurrency.)
- **Pool lifecycle** — `SyncPipe`/`SyncCollection` track `_owns_pool`; borrowed pools are never closed by child pipes; both support `close()`/`terminate()` + context managers (`terminate` on exceptional exit).
- **Chaining** — `SyncPipe._chain()` propagates all runtime settings (context, inputs, ordered, chunksize, error_key, on_error, worker_init); `Context` is authoritative for `inputs`.
- **Pub/sub safety** — `close()`/`send()` remove generator + queue atomically and tolerate exhaustion; receive-queue overflow is logged; user `func` receives only the kwargs it names — unless it accepts `**kwargs`, which opts into all of them. Either way `receive`'s `dfilter` blacklist withholds the pipe's own `conf`/`assign`/`stream`, so naming one is *not* enough to receive it.
- **Timeout** — sync `TimeoutIterator` wraps the upstream read so a blocked read can't overrun the deadline; async `timeout=0` = "no timeout" (matches sync). Full async `anext` cancellation is still `Partial` (ROADMAP §6/§7).
- **Async operator Feed sources** — an async operator called directly with a `Feed` (`AsyncIterable[Item]`, e.g. an async generator) is normalized to an `AsyncIterator[Item]` by `operator.aparse` (the async counterpart of `operator.parse`), and `operator.setup` builds async `tuples`/`orig_stream` when `_input` is an `AsyncIterator`. This is a **lazy pass-through** (never drains the source), so composer operators like `timeout`/`truncate` can bound an infinite `Feed` via the parser (`AsyncTimeoutIterator`'s deadline). Matches `RUNTIME_CONTRACT.md §2`/`§6` and the composer-`Feed` row in `_docs/gameplans/execution-semantics.md` Appendix A. The `AsyncPipe` collection path is unaffected — it still drains at `_materialize_legacy_source` before the wrapper, so the wrapper receives a sync list there.
- **`join` streams its primary and replays only `other`** — `other` is the documented replayed side, so it is the only one that gets a `list()`; the source is iterated lazily and may be unbounded. Never reach for `itertools.product` or `meza.process.join` here: **both tuple every input up front** (`meza.process.join` is literally `map(merge, it.product(left, right))`), which is how the primary silently got materialized in *both* the keyed and the keyless branch — a join over an unbounded source emitted nothing at all. The nested `for x in stream for y in others` form yields in the same order `product` did, so output is unchanged. Guarded by `tests/public/test_pipe_implementations.py`, which asserts **bounded** consumption rather than zero: the operator wrapper reads one item ahead of the parser, so an exact-count assertion would be wrong.
- **`send` completes its targets from a `finally`, and accepts an async source** — `async_hub.complete(others)` used to sit *after* the publish loop, so a `ReceiverUnavailableError` raised by `publish` (an unsubscribed target outlasting `max_wait`) skipped it entirely and every *healthy* receiver blocked forever on a rendezvous channel nobody would close. Completion is channel closure, so it must fire on the exceptional path too — keep it in the `finally`. The loop is also `async for` over `async_iter(stream)`, not a sync `for`: `operator.aparse`/`setup` legitimately hand the parser an `AsyncIterator` for a `Feed` source, and a sync `for` raised `TypeError: 'async_generator' object is not iterable` there. Both guarded in `tests/public/test_pipe_implementations.py`. **The eager `sent` buffer is deliberate, not an oversight** — yielding lazily needs the parser to be an async generator, which the sync-only operator post-parser path would silently emit as a *single item* (`get_assignment` takes its non-`Iterator` branch); that seam belongs to `_docs/gameplans/fanout-topology.md` phase F1, which also renames `others`→`targets` and deletes `complete()`/`ids`. A `strict` xfail marks the spot — don't "fix" it locally.
- **`SyncPipe.subscribe` pins `max_wait=0`, and that is what removes the state markers** — it reads like a disabled timeout; it is the whole design. With `max_wait=0`, `receive.parser`'s `total_waited >= max_wait` is already true on an empty queue, so the `sleep(wait)` + `yield StatefulItem(state=PENDING)` branch is **structurally unreachable** and a subscribed receiver never emits a marker. Don't "restore" a non-zero default, and don't reintroduce a `filterfalse(is_stateful_item, …)` in `SyncPipe._stream` to compensate — that combination is what made `next(receiver)` spin for the full `max_wait` and then `close(name)` itself out of `sync_hub`, killing the channel. Blocking is pointless here regardless: the sync backend has **no producer/consumer concurrency** (`send` pushes only when the sender pipe is advanced, on the same thread), so nobody can satisfy a wait you are blocked inside — blocking is a property of the `Subscription`, not of `receive` (`_docs/gameplans/release-readiness.md` § 2), so `max_wait=0` is the permanent in-process default. The raw `SyncPipe("receive", conf=…)` path still emits PENDING for interleaved manual stepping and `tests/public/test_collections.py` covers it, but the two behaviors coexist **transitionally** — F1/F4 delete `PENDING` outright, so don't harden anything against the raw path's marker contract. An idle drain also wrongly tears down the whole subscription (`close(name)` on the expiry branch); that is **owned by `fanout-topology.md` § 9.2 (F5b) and deliberately deferred to P11** — a local fix would build on the `DONE` sentinel and `send`'s `ids` dict, both slated for deletion by the `Publisher`/`Subscription` rewrite. A `strict` xfail marks it; keep the `yield from` chain generator-native so F5b's `finally` can actually receive `GeneratorExit`.
- **XML hardening** — `parsers.XML_PARSER` disables entity resolution, DTD loading, and network access under lxml (XXE guard).
- **HTTP backend (`_io.py`)** — one backend: all `http(s)` URLs go through `requests` + `raise_for_status()`; `Fetch.__init__` degrades on `requests.RequestException`/`URLError`; memoized paths buffer then close `r`; `r.raw.decode_content = True` always (transparent gzip). **`stream=not memoize`, never `stream=binary`** — the axis is *lazy vs. buffered*, not *bytes vs. text*: both non-memoized branches read `r.raw`, so a text fetch with `stream=False` hands `reencode` an already-consumed body and meza's `Reencoder.__init__` raises a bare `StopIteration` out of `Fetch` (uncaught — it is neither `RequestException` nor `URLError`). Memoized branches read `r.text`/`r.content`, which need the eager request. Guarded by `tests/internal/test_io.py` against a real local server; a fixture file cannot catch this.
- **Compiler JSON path** — `build_pipeline`/`_gen_steps` take a `resolver` (`PipelineResolver`) for sub-pipelines; the terminal `output` node is a passthrough (no `output` module); `gen_modules(embedded=True)` yields only loop submodules; sub-pipelines are called with only their declared kwargs; `_OTHERn` wires aggregate into an `others` list; unresolved leaf modules → `UnsupportedModuleError`, unresolved `pipe_*` → `UnsupportedPipelineError`.
- **Absent field ≠ present-`None`** — `rename`/`regex` look the target field up with a module-level `_MISSING` sentinel (`item.get(field, _MISSING)`) and skip the rule when it is absent, so a rule naming a field the item lacks leaves the item untouched instead of creating it as `None`. A field that is *present* but holds `None`/`0`/`""` is still renamed/rewritten — which is why the check is `is _MISSING`, never truthiness. Absent-field is a runtime data condition (heterogeneous feeds), so it degrades; a missing `conf` key stays a `require_conf` `TypeError`.
- **Call-time `now`, not import-time** — `riko.dates.NOW`/`TODAY` are evaluated once when the module is imported, so they are only safe as epoch-style constants. Anything that stamps or resolves *data* must read the clock per call with `dt.now(UTC)`: `rssitembuilder`'s `pubDate` does it in `parser` (not in `DEFAULTS` — a plain dict cannot hold a lazy value), and `datebuilder` rebuilds its shorthand map per call via `get_switch(now)` (there is no module-level `SWITCH`). Relatedly, **relative-date parsing lives in `riko.cast.cast_datetime`, and nowhere else** — it owns the shorthands, the counted offsets (`"3 days"`/`"-1 month"`, signed or not, singular or plural), and the `next`/`last` word forms, delegating the arithmetic to `riko.dates.get_date` which uses `relativedelta` for months/years. `datebuilder.parser` is a thin wrapper over it (guard with `DateLikeType`, catch `ValueError`, re-raise a pipe-named one). Don't grow a second copy: the old hand-rolled `datebuilder` handled only days/years and let everything else fall through to `dateutil`, which read `"30 minutes"` as *00:30 today* rather than 30 minutes from now. Prefer `dt.now(UTC)` over `cast_datetime("now")` here: the latter is typed `datetime | None`, so it only passes the type check where `reportOptionalMemberAccess` happens to be off.
- **Sort keys must be orderable, cast defaults must be detectable** — two different jobs, and `CAST_SWITCH[t]["default"]` only does the second. A cast default marks "no value", so it must be *detectable* (`NaN` for `float`/`decimal`, `None` for `date`/`datetime`); a sort filler stands in for a missing key, so it must be *comparable* with real values. `_iterutils.SORT_FILLER` (`-inf`) is the filler, and `def_itemgetter` turns `DATELIKE_TYPES` keys into epoch floats via `_date_utils.ensure_tzinfo`/`date_to_datetime` (both taking its `fallback_tzinfo` arg) so `-inf` can compare against them. Never feed `SORT_FILLER` back through `cast_value` — `cast_datetime` raises `AttributeError` on a float and `cast_value` only catches `TypeError`/`InvalidOperation`/`ValueError`; that is why `keyfunc` calls `item.get(attr)` with **no** default and lets the post-cast guard supply it. Two bugs came from conflating the roles: the guard used to replace `NaN` with `NaN` (so `float`/`decimal` sorts silently returned input order), and the epoch date default made `dateformat` emit `01/01/1970 00:00:00` for a missing field.
- **None-vs-falsy specifics** — `listize`: only `None`→`[]` (so `listize(0)==[0]`). Typed-sort default (`_iterutils._resolve_default`) preserves falsy defaults (`0`/`False`), not `""`. DotDict nested assignment guards `existing is not None` (falsy scalars keep working); a missing index/key returns the supplied `default`, not `IndexError`/`KeyError`. `types/guards.py::is_type_value` requires **both** `type` and `value`, so a single-key `{"value": X}` is ordinary nested data and `value` is safe as a nested key — don't relax it back to a one-key check, which silently unwrapped `{"value": X}` to `X` (such nodes are common in real feed data, incl. `riko/data/*.json`). `modules/filter.py` validates each rule's `op` once at prep, then treats missing operands as `None` and skips the comparison.
- **Cast/date/tz** — `cast()` dispatches by destination type; `cast_datetime("now")` returns a `datetime` (`today`/`tomorrow`/`yesterday` stay dates); `CAST_SWITCH["url"]["default"]` is `""`; `dates.ensure_tzinfo` honors `try_local_tz` for zone-less `struct_time`; date arithmetic via `relativedelta` + call-time `now`.
- **Serialization (`_serialize.py`)** — `repr_cache`: `list`/`tuple` get distinct tags; unhashable args bypass the cache (`_UNSUPPORTED` sentinel) rather than colliding. `fromdict` unwraps a union only when exactly one non-`None` member remains (`T | None`); true unions stay un-narrowed. PEP 604 unions handled.
- **Misc** — multi-key sort applies the first rule as primary; joins don't match on both-missing keys; `Chainable` uses signature binding (not exception retry); async temp-file cleanup in `finally`; `fcntl` guarded for Windows.
- **`async_map`** — preserves legitimate `None` results (`_missing` sentinel); `connections=0`=unlimited; eager materialization is by-design (streaming variants: `async_map_stream`/`async_map_ordered_stream`).

## Coding Style

- No comments unless the logic is genuinely non-obvious
- Single `return` statement per function — no early returns
- Return-based error handling; graceful degradation (no `raise` at call sites) for **runtime conditions** (unfetchable url, missing rate, malformed rule): `logger.warning` + carry on, and only when the data contract survives. A **missing required argument** is a call-site programming error and must raise: `require_kwarg` (`riko/modules/_prepare.py`) → `TypeError: the 'aggregate' pipe requires the 'func' keyword argument`. Operand args that must raise: `aggregate`/`udf` `func`, `join` `other`, `send` `others`
- Docstrings follow `_docs/DOCUMENTATION_STANDARD.md` (annotations own types, except `pipe`/`async_pipe` which keep type labels + `conf` nesting and use `Yields:`; STABLE/EXTENSION/PRIVATE tiers; third-person-present summaries; module docstrings keep a `Basic usage::` example; an empty `>>>` after the doctest imports and before each `def`; direct-value doctests; no Twisted/Deferred boilerplate). Run `ruff check --fix` after editing docstrings — it normalizes D213/D413
- Guard optional imports with `try/except`; set a `backend` or flag variable in the `except` block
- `noqa: E302` / `noqa: E704` for overloads — ruff/flake8 conflict on blank lines around them

Details: `_docs/INTERNALS.md`
