# HDX File Proxy API

## Introduction

The hdx-file-proxy is a [`Flask`](http://flask.pocoo.org) powered service that
serves the rows of a csv or excel file hosted on HDX as a read-only JSON API.

Data isn't fetched per request. Instead, `manage populate` downloads one HDX
resource (the `RID` in `config.py`), filters its rows, and loads them into a
database. The API then serves that database table. Re-run `manage populate` to
refresh the data.

## Requirements

hdx-file-proxy has been tested on the following configuration:

- MacOS X 10.9.5
- Python 2.7.10
- postgres (PostgreSQL) 9.4.1

hdx-file-proxy requires the following in order to run properly in development mode:

- [Python 2.7](http://www.python.org/download) (Python 3 is not supported)

Additionally, hdx-file-proxy requires the following in order to run properly in
production mode:

- [postgres >= 9.4](http://www.postgres.org)

## Setup

### local

(You are using a [virtualenv](http://www.virtualenv.org/en/latest/index.html), right?)

```text
pip install -r requirements.txt
export CKAN_API_KEY=<your HDX API key>
manage setup
manage populate
manage serve
```

The `manage` command is provided by the `manage.py` package in
`requirements.txt`; `python manage.py <command>` works as well.

**Note:** `manage` runs in `Development` mode by default, which only loads the
first 50 matching rows (`ROW_LIMIT`). Use `manage -m Production populate` to
load every matching row.

### Production

Production mode uses the postgres database set in `DATABASE_URL`, or
`postgres://reubano@localhost/app` if it isn't set, so create that database
first.

```text
pip install -r prod-requirements.txt
sudo -u postgres pg_ctl start
export DATABASE_URL=postgres://<user>@localhost/<database>
manage -m Production setup
manage -m Production populate
gunicorn "app:create_app('Production')" -w 3 -k gevent
```

## Data

### Source

`manage populate` fetches the HDX resource `RID` from `ENDPOINT` (see
[Configuration](#api)) using the CKAN API, then downloads the file at the
resource's `perma_link` (or `url`). The file must be a `csv`, `xls`, or `xlsx`
file, and must contain the columns listed in [Fields](#fields).

### Filter

Only rows matching **all** of the following are loaded (case-insensitive):

Column | Value starts with
-------|------------------
`adm0_name` | `a` (countries whose names start with "A")
`mp_month` | `3` (March)
`mp_year` | `2015`

The filter is hardcoded in `fetch_data` (`app/utils.py`); edit `constraints`
there to load different rows.

### Refreshing

Each `manage populate` run deletes every existing row before inserting the
newly fetched ones, so the table always reflects the latest file.

### Fields

Each row of the `data` table (the `Data` model in `app/models.py`) has:

Field | Type | Description
------|------|------------
`id` | integer | Auto-incrementing row id
`adm0_name` | string | Country name
`adm1_name` | string | First-level administrative area
`mkt_name` | string | Market name
`cm_name` | string | Commodity name
`mp_month` | string | Month of the price observation (`1`–`12`)
`mp_year` | integer | Year of the price observation
`mp_price` | number | Price
`utc_created` | datetime | When the row was loaded
`utc_updated` | datetime | When the row was last updated

## Usage

hdx-file-proxy is intended to be used via HTTP requests. All endpoints are
prefixed with `/v1`, served on port 3000 by default, and only accept `GET`.

Endpoint | Description
---------|------------
`GET /v1/` | Welcome message (plain text)
`GET /v1/data` | Query the loaded rows
`GET /v1/data/<id>` | A single row

The `/v1/data` endpoints are generated by
[Flask-Restless](https://flask-restless.readthedocs.org/en/0.17.0/) from the `Data`
model. Results are paginated with the `page` and `results_per_page` parameters (max
1000), and can be filtered and sorted with the `q` parameter (see the
[Flask-Restless docs](https://flask-restless.readthedocs.org/en/0.17.0/searchformat.html)).

### Examples

#### cURL

*Get the loaded rows*

```bash
# request
curl http://localhost:3000/v1/data

# response
{
  "num_results": 1,
  "objects": [{
    "adm0_name": "Afghanistan",
    "adm1_name": "Badakhshan",
    "cm_name": "Bread",
    "id": 1,
    "mkt_name": "Fayzabad",
    "mp_month": "3",
    "mp_price": 50.0000000000,
    "mp_year": 2015,
    "utc_created": "2015-10-28T04:02:14.556843",
    "utc_updated": "2015-10-28T04:02:14.557005"
  }],
  "page": 1,
  "total_pages": 1
}
```

*Get bread prices, highest first*

```bash
curl -G http://localhost:3000/v1/data \
  --data-urlencode 'q={"filters":[{"name":"cm_name","op":"eq","val":"Bread"}],"order_by":[{"field":"mp_price","direction":"desc"}]}'
```

#### Python

initialize

```python
# init requirements
import requests

endpoint = 'http://localhost:3000/v1'
```

*Get the loaded rows*

```python
# request
r = requests.get('%s/data' % endpoint)

# response
r.json()
# same as cURL above
```

*Get bread prices, highest first*

```python
import json

q = {
    'filters': [{'name': 'cm_name', 'op': 'eq', 'val': 'Bread'}],
    'order_by': [{'field': 'mp_price', 'direction': 'desc'}]}

r = requests.get('%s/data' % endpoint, params={'q': json.dumps(q)})
r.json()['objects']
```

## Configuration

### API

All configuration options are available in `config.py`:

Option|Description|Default
------|-----------|-----------
ENDPOINT|The HDX url|<https://data.hdx.rwlabs.org>
RID|Resource id of the file you wish to fetch|b5b850a5-76da-4c33-a410-fd447deac042
API_KEY|Your HDX API Key|`CKAN_API_KEY` environment variable, or `MY_API_KEY`
HOST |The server host| `127.0.0.1` (`0.0.0.0` in Production mode)
PORT |The server port| 3000 (or the `PORT` environment variable)
API_URL_PREFIX |Prefix for all API endpoints| `/v1`
API_MAX_RESULTS_PER_PAGE |Max `results_per_page` for `/v1/data`| 1000
DEBUG |Enable the Flask debugger| False
TESTING |Testing mode| False
PROD |Production mode| False
CHUNK_SIZE |Number of rows to insert at a time| 10000
ROW_LIMIT |Total number of rows to load| 0  # All

### Modes

Select a mode with `manage -m <mode>` (`Development` by default) or
`create_app('<mode>')`.

Mode | Database | Overrides
-----|----------|----------
Development | SQLite `app.db` | `DEBUG=True`, `CHUNK_SIZE=10`, `ROW_LIMIT=50`
Production | `DATABASE_URL`, or postgres `postgres://reubano@localhost/app` | `PROD=True`, `HOST=0.0.0.0`
Test | SQLite in memory | `TESTING=True`, `ROW_LIMIT=10`

Alternatively, pass a config file with `manage -f <file>`, or set the
`APP_SETTINGS` environment variable to a config file path.

### Environment variables

hdx-file-proxy uses [ckanapi](https://github.com/ckan/ckanapi) to talk to HDX and reads
the following
[Environment Variables](http://www.cyberciti.biz/faq/set-environment-variable-linux/) if
set:

Environment Variable|Description
--------------------|-----------
CKAN_API_KEY|Your HDX (CKAN) API Key
DATABASE_URL|Production database url (also sets the Heroku `SERVER_NAME`)
PORT|Server port
APP_SETTINGS|Path to a config file

## Scripts

hdx-file-proxy comes with a built in task manager `manage.py`.

Command | Description
--------|------------
`populate` | Fetch the HDX resource and (re)load the filtered rows
`serve` | Run the dev server (`-h` host, `-p` port, `-t` threaded)
`setup` | Clear the database and create new tables
`createdb` | Create the database tables
`cleardb` | Remove all tables
`lint` | Check style with flake8
`test` | Run nose tests (`-x` stop after first error)

### Examples

*View all available commands*

```bash
manage
```

*Run python linter and nose tests*

```bash
pip install -r dev-requirements.txt
manage lint
manage test
```

**Note:** the test suite (`tests/test_site.py`) was copied from hdx-age-api and
currently fails on import.

*Run dev server on custom port and with multiple threads*

```bash
manage serve -tp 3001
```
