# Recreating a JSON definition for a compiled example pipe

The `examples/pypipelines/pipe_*.py` modules are **generated** — each is compiled
from a sibling `examples/pipelines/pipe_*.json` pipe definition by `compile-pipe`
(the same `pipelines/` + `pypipelines/` split as `tests/`). This guide records how
those JSON files were reverse-engineered from the old, source-less
`# generated by pipe2py` modules, so the same recipe can recreate a JSON for any
other compiled python pipe.

## The pieces

- **`riko.compile.compile_pipe(pipe_def, name)`** turns a JSON `PipeDef` into the
  module source string (this is what `compile-pipe` calls).
- **`riko.compile.build_pipeline(parse_pipe_def(pipe_def, name))`** runs the same
  definition in-process, returning the stream — use it to check behavior while
  iterating, without writing a file.
- Reference definitions live in `tests/pipelines/*.json` with their expected
  output in `tests/pypipelines/*.py`. Grep these for a module you need
  (`grep -l '"type": "regex"' tests/pipelines/*.json`) — they are the ground
  truth for a module's JSON shape.

## The `PipeDef` shape

```json
{
  "modules": [
    {"id": "sw-1", "type": "<pipe name>", "conf": { ... }},
    {"id": "_OUTPUT", "type": "output", "conf": {}}
  ],
  "wires": [
    {"id": "_w1",
     "src": {"id": "_OUTPUT", "moduleid": "sw-1"},
     "tgt": {"id": "_INPUT",  "moduleid": "_OUTPUT"}}
  ]
}
```

- Every module needs a `conf` key, even if `{}` (a missing `conf` raises
  `KeyError: 'conf'`).
- Scalar conf values are `{"type": "text", "value": "..."}` (or `"bool"`, `"int"`,
  `"url"`, ...).
- The terminal `output` module is where the stream ends; wire the last real
  module's `_OUTPUT` into its `_INPUT`.

## Steps

1. **Read the old module.** Each `sw_<n> = <pipe>(...)` line is one module; the
   arguments are its `conf` and per-call kwargs. The order of the assignments is
   the wire order.
2. **Map each call to a module dict.** Copy the `conf` verbatim (values are
   already in `{"type", "value"}` form in the old source), and give each module a
   short `id` (`sw-1`, `sw-2`, ...). The generated variable names derive from the
   `id`, so pick whatever reads cleanly.
3. **Turn kwargs into module-level keys.** A per-call kwarg such as `assign=` or
   `field=` becomes a sibling key of `conf` on that module (e.g.
   `{"id": "sw-2", "type": "strreplace", "conf": {...}, "field": "author",
   "assign": "author"}`). Pass a **plain string**, not a `{"type","value"}` dict —
   see gotchas.
4. **Wire the modules.** One wire per hop, `src._OUTPUT` → `tgt._INPUT`, ending at
   `_OUTPUT`. For terminal wiring (feeding one module's output into another's
   named input, e.g. an `itembuilder` attr or a `dateformat` `format`), set the
   attr value to `{"terminal": "<name>", "type": "text"}` and target that name:
   `"tgt": {"id": "<name>", "moduleid": "sw-N"}`. The compiler passes it as
   `"<name>"=sw_M`.
5. **Iterate against `build_pipeline`.** Compile and run until the output is what
   you want. This is where the old, subtly-broken pipes were fixed.
6. **Write both files.** `examples/pipelines/pipe_<name>.json` (the source of
   truth) and the regenerated `examples/pypipelines/pipe_<name>.py`.

## Regenerate + drift guard

Regenerate one module:

```bash
compile-pipe examples/pipelines/pipe_<name>.json -o examples/pypipelines/pipe_<name>.py
```

Or regenerate every compiled pipe (both `tests/` and `examples/`) at once, the
same way `gen-config`/`gen-names` regenerate their outputs:

```bash
gen-pipelines            # or: manage codegen -m pipes
```

`tests/internal/test_example_pipes.py` recompiles every
`examples/pipelines/pipe_*.json` and fails if the committed
`examples/pypipelines/*.py` drifts — the same guard `tests/pypipelines` uses.
Generated modules keep their `# ... generated by riko` header (no docstring) and
are exempted from a few lint rules via `[tool.ruff.lint.extend-per-file-ignores]`
(`examples/pypipelines/*`).

## Gotchas found while doing this

- **`field=` must be a plain string.** Passing `{"type":"text","value":"author"}`
  makes `strreplace` operate on the whole item (the original bug). Use
  `"field": "author"`. For `regex`, the field lives **inside the rule**
  (`conf.rule[].field`) — the original `pipe_a3d1...` omitted it and raised
  `RegexConfRule ... missing 'field'` only when the stream was actually drained.
- **`datebuilder` reads the item's `content` field**, not conf. Feed it from an
  upstream `itembuilder` that builds `{"content": "12/2/2014"}`; putting the date
  in `datebuilder`'s conf self-references and yields `unrecognized date None`.
- **`dateformat` reads the `date` field** (`OPTS = {"field": "date"}`) and a
  missing field yields `""`. Chain it after a `datebuilder` that `assign`s to
  `date`, or `emit` the value into the next module's terminal.
- **`dateformat` has no `timezone` setting** (`DateFormatConf` only has `format`).
  A wired/conf `timezone` is silently ignored — the output stays UTC. This is why
  `examples/{pipelines,pypipelines}/pipe_timezone.*` exists with a **strict xfail**
  (`tests/functional/test_examples.py::TestExamples::test_unsupported_timezone`):
  if timezone support ever lands, the xfail flips and flags the doc.
