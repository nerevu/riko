# Audit tests (find and verify, don't fix)

The audit request is: $ARGUMENTS

The deliverable is a findings report. Do not modify any file, the git index, or a
test. Fixes happen afterwards through /triage, or as slices the user approves, and
the `move_tests.py` modes do the mechanical part.

The rules the audit checks against already have owners. Read them; don't restate
them in the report, cite them:

| Rule | Owner |
|---|---|
| tier, subject → file, class layout and order, tables, helpers, split/merge, search-before-adding | `tests/__init__.py` docstring |
| per-file subjects | `tests/<tier>/__init__.py` (generated by `manage codegen --tests`) |
| doctest vs pytest ownership | `_docs/DOCUMENTATION_STANDARD.md` (removing-examples rule 6 and "Doctests and unit tests share coverage") |
| layer jobs, pytest vs `manage lint` ownership, enforcement, protected tests | `_docs/gameplans/testing.md` §1, §3, §5 |
| timeout as backstop only | `tests/_timeouts.py` docstring |
| timeout bounds and their ladder | `tests/__init__.py` docstring |
| per-change checks | `.claude/skills/tidy/SKILL.md` §3.9 |
| scanner sections and thresholds; mover modes | headers of `.claude/skills/tidy/overlap_scan.py` and `move_tests.py` |

`manage lint --tests` already enforces indexing, `Test<Subject>` classes, no
top-level tests, no private imports in `public/`, size advice, bounds on the
ladder and below their outer bound, and no tracked-doc reads. Don't report
what the lint catches; run it and cite any failure once.

## 1. Resolve the scope

- **Whole suite** (no args, "all"): every tier plus the collected doctests.
- **A tier or named files**: those files, compared against the rest of the suite
  and the doctests. An overlap is only visible from both sides.
- **Since a commit**: test files changed in `git diff <ref>...HEAD` plus any new
  untracked ones, and the source files whose doctests changed.

State the scope with file and line counts (`wc -l tests/*/test_*.py`) and the
baseline: `uv run --active pytest --collect-only -q --no-cov | tail -1`, plus the
per-file counts.

## 2. Script first, then agents verify leads

Reading the suite by hand is the expensive mistake. Four agents once spent
150–250k tokens each on a sweep that `overlap_scan.py` now does in about 2 s. Run
the mechanical sweeps yourself in the main loop (`SCRATCH` is the session scratchpad):

```bash
python .claude/skills/tidy/overlap_scan.py [--files F ...] --json > "$SCRATCH/scan.json"
uv run --active python -m riko.cli.manage lint --tests
uv run --active pytest --collect-only -q --no-cov > "$SCRATCH/ids-head.txt"
```

Add these only when their dimension is in scope:

- **Tripwires:** `pytest --runxfail -q --no-cov -rf <files>` shows *why* each
  strict xfail fails today.
- **Bounds and speed:** `pytest -n auto --no-cov --durations=0` three times; keep
  each test's worst `call` time.
- **Unique coverage:** `COVERAGE_CORE=ctrace pytest --cov=riko --cov-context=test`
  ranks suspects that add no unique lines. It only ranks; it never decides.

Before fanning out, estimate the cost: lines to read × about 12 tokens × the number of
agents rereading them. Size each file group to fit a 100k-token agent: about 1k test
lines. An agent starts with about 50k of fixed context, and verifying costs about 23
tokens per assigned line in tool results plus about 500 per turn (2–4.5k-line groups
ran all eight agents of the 2026-10-29 audit to 145–189k). Split agents by file group
(`model: "opus"`), give each agent the scan leads for its files, and require both
sides of every suspected duplicate to be read. Tag each lead CONFIRMED or DROPPED,
with the reason. Every brief ends with: "Run `date` at the start and between items. If
you pass about 10 minutes or 100k tokens and the remaining work is mechanical, stop at
a consistent point and report what is done, what is left, and the script that would
finish it." Ping each agent for status at about 10 minutes. When an agent finishes,
inspect any scripts it wrote and promote each one, fold it into
`overlap_scan.py`/`move_tests.py`, park it in `.claude/skills/drafts/`, or drop it.

## 3. Dimensions, in risk order

1. **Tests that cannot fail.** Look for:
   - a strict xfail satisfied by a setup error (a fixture that is a plain
     generator, a missing name) instead of the documented failure;
   - no assertion, or assertions inside a loop over an empty collection;
   - a lookup of the wrong key compared against `None`;
   - a test that asserts a test helper rather than a riko name;
   - two tests asserting opposite outcomes for one pending feature;
   - a "…_once" test that never counts.
2. **Tests that end only by timeout.** Look for:
   - blocking work inside a nested coroutine or the code under test that outlasts
     its backstop, so a regression ends by the timeout firing or passes on its own;
   - an operation with no `fail_after`;
   - a process-spawning test with no `timeout` marker.

   `manage lint --tests` flags a literal `sleep` on the test's own path that lasts
   as long as its marker or backstop; the shapes above are the audit's.

   A test guarding "stops promptly" needs blocking work longer than its
   elapsed-time assertion but shorter than the backstop.
3. **Same behavior asserted twice**, which the scanner mostly misses:
   - a cross-tier twin of a different shape (a direct `_PoolLifetime` call vs an
     end-to-end `Pipeline` run);
   - a doctest example repeated as a `pytest.param` row (short literals such as
     `"8"` or `"many"` fall under `MIN_STR`);
   - a doctest error case repeated as a `pytest.raises` row;
   - CLI tests re-pinning error text that another test owns;
   - two tripwires for one pending capability (merge them, never delete one).

   Grep the behavior's vocabulary (the setting, error type, message fragment, or
   outcome) across `tests/` and `riko/`, and open every hit. A hit you saw but
   never opened is exactly how a duplicate was added on 2026-10-29.
4. **Doctest balance.** A doctest grown past basic usage (move cases to the
   subject's table), or an edge case in both places. Apply rule 6 as written; there
   is no public/private tie-breaker and no rule that "an error case stays in the
   doctest".
5. **Same-shape groups.** The scanner's `shapes` section, plus tests that share
   setup and assertion and differ only in data. A finding must estimate the line
   count after the fold. A fold that would grow the file is not a finding until
   its rows compact.
6. **Misfits.** Wrong tier, a class whose subject another file's row owns, a class
   named for something that isn't a riko name, behavior/rejection/tripwire order,
   grab-bag or history-named files, and files that need a split or merge (trim and
   move first, then split by concept). Also a **test that should be a lint**: its
   assertion's input is a tracked Markdown or prose file (not a `tmp_path` fixture,
   generated Python, or an RST doctest), so editing text rather than code fixes a
   failure. `manage lint --tests` flags a doc path built from `ROOT_DIR`,
   `DOCS_DIR`, `PACKAGE_DIR`, `TESTS_DIR`, or `__file__`, and a `Path`/`open` of a
   `.md`/`.rst` name; grep `tests/` for what it misses (`os.path.join`, a path held
   in a variable): `_docs/`, `.md`, and `read_text(`, and open each hit. The fix
   is an offender function under `manage lint --docs` plus a fixture-text unit
   test of it (`testing.md` §1).
7. **Helpers.** Single-user `tests/_*.py` names, identical definitions across
   files, 3+ inline copies that should be one helper, and placement.
8. **Timeout bounds.** `manage lint --tests` checks ladder membership and
   nesting; the audit measures the fit: every bound is the smallest ladder step
   at least five times the worst of the three `--durations` runs above. Map a
   marker to the `def` that *follows* it, never by line range.
9. **Stale citations and names.** Test names that cite nothing (`test_documented_*`),
   old verbs in test names, and `_docs/` citations of tests that moved or were
   deleted (`lint --docs` checks `path::Class::test`; it misses prose mentions).
10. **Speed.** The slowest tests by `--durations`, duplicated subprocess matrices,
    and pools spun up where one call would do.

## 4. Known false positives

Drop a lead that matches one of these unless something else confirms it:

- **Cov-context "no unique lines"**: contract and surface tests (`test_imports`) hit
  the same import lines by design. Line coverage cannot tell a redundant assertion
  from a distinct one.
- **Same name in two files**: usually a sync/async mirror, which stays.
- **Same shape**: kept when the name states a distinct rule, when it is a sync/async
  twin, when a setup differs (a pipe that must stay unpicklable, an extra
  `__cause__` check), or when the fold needs builder lambdas or multi-line rows.
- **Same literals**: not a duplicate when the input or the entry point differs
  (`Pipeline.with_resource` vs `Context.with_resource`, `.map(**kw)`).
- **Shared-helper flags** on a factory that the async half of a twin pair also uses.
- **Repo files as test input**: the generated-file drift guards in `test_codegen.py`
  (`_configs.py`, `_names.py`, `_module_ids.py`, `pyworkflows`) compare generated
  Python with its generator, which `testing.md` §1 gives to internal tests; a matrix
  derived from `pyproject.toml` (`SCRIPTS` in `test_cli.py`) derives input and asserts
  nothing about the file. Neither is a test that should be a lint.
- **Ruff noise on tests**: RUF029, ARG, and PLR2004 hits are mostly protocol-shaped
  fakes and fixture data; ERA is already enforced.
- **Re-read failures**: past audits withdrew claims after reading both sides. The
  two tests went through different code paths, the "duplicate" also asserted a
  logged warning, or the pytest copy was stricter than the doctest, so the doctest
  had to be strengthened first.

Protected (report, never propose deleting): every strict xfail and its owner, the
tests `testing.md` §5 protects (`test_parallel` and the core lifecycle tests), sync/async mirrors, and tests a
gameplan cites by name as a guard.

## 5. Verify before reporting

- **Redundant:** name the covering test or doctest (`path::Class::test` or
  `module.symbol` doctest) and confirm both share the input *and* the outcome.
  When the copy being cut asserts more, say what moves across first.
- **Cannot fail:** demonstrate it. Simulate the regression (patch the fix out, or
  run `--runxfail`) and show the test still passes, or fails for the wrong reason.
- **Fold:** list the rows, the ids, and the estimated lines saved. Every removed
  test maps to a row, and no row's data changes silently.
- **Deletion:** flag any line that only the cut test executes. The ratchet total
  can't see a deleted test whose lines other tests also reach, and earlier
  "mechanical" slices lost 14 lines that way.
- **Speed and bounds:** cite the measured times, not estimates.

A lead you cannot substantiate is dropped, or reported as unverified with what
would confirm it.

## 6. Report

Group by dimension within severity: **can't fail** and **ends by timeout** first,
then **duplicates**, then **layout**, **bounds**, and **speed**. Each finding gets:

- a one-line title with `tests/…py:line` evidence, and the covering test where one
  applies;
- the concrete consequence (the regression it hides, the lines or tests it saves,
  the seconds it costs);
- the rule it breaks, cited by owner file from the table above;
- verified/unverified status;
- the mechanical fix it implies (`move_tests.py --delete/--drop-row/--merge/--place`,
  a new table row) as a hint for triage, not something applied.

Close with:

- **Totals**: tests and lines before, and the projected count after the proposed
  cuts.
- **Scope covered**, and anything skipped.
- **Triage handoff**: each finding marked phase-owned (tripwire / gameplan row),
  local, or needs a decision. Triage is always the next step.
- **Slice plan for the fix**: broken tests first, then layout moves, then
  dedup/folds, then rules or lints. Each slice is verified by a sorted collect-id
  diff against a clean HEAD worktree (only the stated deletions differ),
  `codegen --tests`, `lint --all`, `test --ratchet`, and `--check-types`.
- **Tool gaps**: leads the scanner missed that you found by hand, with the
  `overlap_scan.py` section or lint that would catch them. A miss matching an open
  candidate in the "Pending tooling" list of `_docs/gameplans/testing.md` §3 is the
  trigger for building it.
- **Script candidates**: any agent that ran past about 10 minutes or 50 tool calls
  on mechanical work, with the script it suggests.
  Save each candidate's draft (or the agent's own script) in `.claude/skills/drafts/` with a header docstring (purpose, inputs, outputs, origin date), and cite that path in the report and handoff.
